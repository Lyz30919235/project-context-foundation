# 运行手册

## 使用前提

- 先确认适用规则、当前任务允许的操作，以及本仓库根目录和工作区状态。
- 本手册提供操作方法，不构成执行授权。只读任务不得因看到操作步骤而改动文件。
- 本轮验证结果统一见 [NOW 的核验与证据](NOW.md#核验与证据)。下列命令是操作步骤，不代表已执行成功。

## 文档维护与检查

1. 根据 [项目索引](../../PROJECT_INDEX.md#职责与路由) 定位当前问题及权威来源。
2. 搜索相关标题、关键词或符号，读取命中处及必要上下文；修改前确认目标内容及已有成果。
3. 定点修改。若入口或职责变化，同时修订索引和直接关联链接。
4. 检查本次涉及的文件：规则是否完整、职责是否明确、事实是否有依据、相对链接及目标章节是否存在、是否重复保存权威正文。
5. 检查差异及空白错误；首次提交前还需核对未跟踪的新文件和暂存区内容。

在仓库根目录可使用以下 Git 检查命令：

    git status --short
    git diff --check
    git diff --cached --check
    git diff --cached --stat

新文件未暂存时不出现在普通 git diff 中；应核对本轮新文件清单，暂存后再审查实际内容。链接检查仅覆盖本次改动及直接关联目标，不扩展扫描无关目录。

## Git 提交与公共同步

前置条件：Git 可用，提交身份已配置，具备仓库认证权限，目标远端已核实，且当前任务允许相应修改与公开同步。远端权威入口见 [MAP](MAP.md#版本与远端)。

1. 核对工作区差异，只将本轮审查过的实际文件路径传给 git add --；不得暂存无关改动或认证文件。
2. 审查暂存差异并完成必要检查，使用说明真实改动的提交信息执行 git commit。
3. 向已核实的远端和分支推送。本仓库约定远端 origin、分支 main：

       git push -u origin main

4. 推送后比较以下命令返回的本地提交与远端 main 提交，确认哈希相同，并检查工作区状态：

       git rev-parse HEAD
       git ls-remote --exit-code origin refs/heads/main
       git status --short

5. 在 GitHub 仓库页面或无需认证的仓库 API 中确认仓库为 Public；保存必要的对象、日期、核验范围与证据入口，当前状态直接修订到 NOW。
6. 如遇认证、网络、冲突或保护规则阻塞，保留本地成果并如实报告失败环节；成功提交不等于成功推送。

此流程要求同步每个完成的改动批次，不要求为每个文件单独创建提交。不得用强制推送或覆盖他人成果处理常规同步失败。

## 业务运行与验证

离线游玩：用浏览器打开 [map.html](../../dist/map.html)，或双击 [打开map.cmd](../../打开map.cmd)。离线入口已内嵌绘图资源、碰撞和脚本，不需要服务器或网络依赖。

开发命令在仓库根目录执行，前提为 Node.js 可用；无需 npm install：

    npm run build
    npm test
    node scripts/validate-level.mjs
    npm run dev

构建更新 dist/index.html 与 dist/map.html；规则回归验证碰撞、收集、门锁和传送；实际关卡验证器使用同一引擎逐格移动，成功时输出 won=true。开发服务器默认位于 http://127.0.0.1:4173，仅用于本机预览，退出时停止本任务启动的服务器。

修改地图：编辑 [标注](../../src/map.annotations.json)，准备 Python 及 [数字化依赖](../../scripts/requirements-map.txt)，再执行：

    python -X utf8 scripts/digitize-map.py
    npm run build
    npm test
    node scripts/validate-level.mjs

数字化输出 src/level.generated.json；不能以生成成功替代可达性验证。依赖安装是按需的前置操作，不是每次游玩必需。

浏览器检查范围按改动选择：开始探索、键盘/点击行走、碰撞、缩放及相机边界、暂停/恢复、保存与重开；触屏真机和真人完整通关需单独标注。

发布使用 Sites 的同一 project_id，按其工具流程将精确源码提交推送到源仓库，打包 dist 后保存并部署该版本；GitHub origin 仍按上文单独同步。认证令牌只保留在会话内存，经标准输入传入工具，不写入文件或命令参数。部署成功以发布工具返回的终态和地址为准，执行结果见 NOW。
