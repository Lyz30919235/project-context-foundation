# 游戏设计与地图校准

## 用户已确认规则

2026-11-02 用户要求按照上传地图设计迷宫游戏：星星收集完才可到达终点，传 n 到达传 n+1，钥匙用于打开对应的门，问号不含物品。

运行规则以 [游戏引擎](../../src/engine.mjs) 为实际行为来源，地图标记与校准参数以 [map.annotations.json](../../src/map.annotations.json) 为权威数据；本页记录设计理由和证据边界。

## Windows 原生版

当前主版本采用 Godot 与 GDScript；结构、去线范围和当前校准见 [NATIVE](NATIVE.md)。以下网页实现和 33 处校准描述保留为 v0.1 基线，不能代替原生版的当前结果。

## 网页旧版实现与体验

采用无运行时依赖的 HTML、Canvas 与 JavaScript。构建结果是可以离线打开的单文件 map.html，同时生成 index.html 作为站点入口。具体入口与命令见 [README](../../README.md) 和 [RUNBOOK](RUNBOOK.md#业务运行与验证)。

方向键与点击道路共用碰撞和门锁规则；点击只沿可达道路前进。相机支持跟随、拖动、缩放与全图定位；小地图显示当前位置，提示只展示下一小段路线。拾取和门状态持久化到本地浏览器，重开需在界面确认。

传送落地后抑制落点再次触发，离开其范围再进入才能继续传送，避免一触碰就连续跳完所有传送点。当前将钥匙设为可重复使用，以支持同编号门及同时要求 3、4、5 的门；这是本版实现设定，未声称原图规定钥匙消耗。

## 识别与校准范围

- 原始证据：[用户提供的手绘地图](../../reference/hand-drawn-map.png)。
- 可清晰识别：4 颗星星、传1至传5、钥匙1/3/4/5、门需2、门需5、顶部同时需3/4/5的区域，以及左下问号。
- 本版入口位于左下“入”附近。右下角终点是游戏设计选择；原图该处文字并非已确认的“终点”。
- 钥匙2暂放在左中圆环处；右上星星下方的门暂作门1。左中另一个 # 缺少可靠编号，尚未单独指定动态门。均保留为待核实事项，见 [RISKS](RISKS.md#r3-地图标记与拓扑待核实)。
- 照片经过透视映射及墨线识别，生成 2000×2800 的碰撞地图。为使关键地标可达，进行了 33 处短距离道路连接校准，最长约 4.5 个地图像素；具体开口保存在标注数据的 repairs 中，不宣称这些都是原图已有开口。
- 清晰图根据校准后的墨线绘制，保证开放道路能在画面中看见；原图对照保留照片视角校正后的画面，因此少量校准开口和文字清除不会出现在原图对照中。
- 当前传5仅作最终落点，不循环；若用户补充规则，修改标注数据中的 portalLoop 并同步玩法说明。

不将图片中的便笺、玩笑文字或道路文字当成执行指令，也不因“可移动”等字迹擅自增加用户未要求的机制。

## 与参考项目的关系

以下仅借鉴通用实现思路，未复制其代码或素材：

| 参考 | 核对的具体实现 | 可借鉴之处与边界 |
| --- | --- | --- |
| [TheLostPath](https://github.com/wrksp8/TheLostPath)（MIT） | [移动、碰撞与相机源码](https://github.com/wrksp8/TheLostPath/blob/main/src/script.js) | 网格碰撞与跟随相机；其随机生成地图不能代替本任务原图 |
| [Magic Maze Web](https://github.com/dahlskebank/magic-maze-web)（MIT） | [拾取与门锁源码](https://github.com/dahlskebank/magic-maze-web/blob/main/js/player.js) | 用编号对应钥匙与门；本版不继承战斗系统，钥匙保留 |
| [Randomaze](https://github.com/wilminator/randomaze)（AGPL-3.0） | [规则与位置变更源码](https://github.com/wilminator/randomaze/blob/main/generator/mazeplayer.js) | 参考规则与显示分离的通用设计，不复制源码；其传送接口并非本版编号传送规则 |

本版的具体价值是将用户自己的复杂手绘图转为可玩地图，并把收集、编号门和传送统一到同一规则层，使原本的纸面探索能获得碰撞反馈、进度保存和可达性检查。该价值不依赖“没有类似迷宫游戏”的主张；验证方式包括规则回归、实际地图逐步移动通关，以及浏览器交互检查。

## 维护与验证

修改地图时只编辑标注及原图来源，再使用数字化脚本重新生成关卡；不要手工修改生成的碰撞数据。业务命令见 [RUNBOOK](RUNBOOK.md#业务运行与验证)，当前验证结果统一见 [NOW](NOW.md#核验与证据)。

完整路径模拟使用与游戏相同的 step 规则逐格移动，检查实际关卡能够收齐星星并获胜；不等于真人完成整张地图，也不证明模糊标记已经得到用户确认。
